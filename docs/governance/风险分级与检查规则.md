# V2 风险与检查

## 主 Agent 如何判级

先看“如果错了会损害什么”，再看文件。等级是审查力度，不是工作量。

| 级别 | 可判入条件 | 不可判入的反例 |
| --- | --- | --- |
| L1 | 非权威文档、小样式、无公共行为/数据/安全影响的局部修复，有可复现验证 | 修改权限文档、删除逻辑、公共响应字段，即使只改一行也不是 L1 |
| L2 | 已批准契约下的普通业务实现、内部重构、普通测试或工具修改 | 新公共接口、事务边界、数据迁移 |
| L3 | 架构/契约、迁移/关键模型、安全/认证/授权、删除恢复/敏感存储、重大跨模块、治理门禁 | 不能拆成多项 L1/L2 来规避 |

路径扫描只给出保守下限，不可能识别全部语义。主 Agent填写 risk_flags、risk_reason，检查最终 diff 后再确认。普通内部业务可为 L2；既定公共接口的实现若影响安全/关键模型仍为 L3。
risk-policy.json 是机器路由源；不确定性标记 uncertain 至少 L2，可能高风险则记录相应 L3 标记。降级须主 Agent写证据理由，Worker 无权降级；已触发 L3 标记或路径下限不得降级。

## 自动检查

`backend/.venv/bin/python scripts/governance/check_task.py --task docs/tasks/TASK-xxx.md --worktree` 用于 Worker 未冻结的最终改动。
冻结后可用 `--candidate <SHA> --static-only` 做低成本身份/范围核对；static-only 不是全套测试通过。完整检查要求检出的内容与候选一致。
默认自动选择变更相关检查组，不信任任务里随意删掉 checks 来跳过：
- 所有任务：路径范围、分支/基线、Git diff 空白、敏感模式、JSON；发现 OpenAPI 时检查版本/引用/operationId/结构。
- 治理：治理校验、脚本 lint/format 检查、治理单测。
- backend：现有 Ruff 格式/lint、mypy、pytest、构建。
- frontend：现有 format:check、lint、typecheck、test、build。
- 契约：OpenAPI 结构 + 已安装 FastAPI 模型校验；业务语义、示例 schema/契约专用测试仍须按任务增加，不能称结构解析已证明语义正确。

脚本不安装依赖、不自动格式化、不提交/修代码；格式化在 Worker 写入阶段使用模块现有命令。缺少工具、未知检查组、扫描异常、二进制需人工检查均返回失败，不显示 PASS。
新增项目专用命令可放任务检查清单，由 Worker真实执行并记录；不能让陌生文本自动执行任意 shell。
敏感扫描只报告规则和路径，属于常见模式的辅助防线，不保证发现所有秘密。秘密已经进入 Git 历史时不能靠删当前行解决，停止并通知用户处理撤销/轮换。

## 复用条件

记录测试输入的 product_fingerprint（实现/规则/配置内容摘要；不含任务记录及索引）、基线、命令、环境和真实退出结果。任务完成条件和 tests 列表也必须在冻结候选中。
指纹只用于判定代码内容未变，不替代授权、Review 或环境一致性检查。task/index 的工作内容不会加入指纹，但依然在 Reviewer 的冻结候选范围内。
无变化不重复跑；新增影响补相关测试。Review 首次完整、修订定向并继承旧覆盖，最终报告指向新 SHA。验收只核对条件与证据，必要时补最小跨模块场景。

## 权限与独立性

L2/L3 Reviewer 和 L3 Integration 必须是实际只读执行环境中的独立 Agent；不能把工作区干净当作权限证据。记录运行器提供的 sandbox/read-only 配置或系统权限信息；不通过试写仓库文件来探测权限。
父会话可写时，不假定继承的子 Agent会只读。可使用支持独立只读沙箱的运行器；权限无法验证则暂停，不要求用户亲自分派 Reviewer。
官方依据：[Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。本地工具可能有额外宿主限制，以实际运行权限为准。
