# StudyPilot Agent 角色与模块边界

## 1. 使用原则

- 角色表示长期职责，任务单表示本次授权。
- 拥有某个角色不代表可以随时修改对应文件。
- 写入必须同时满足角色职责、任务允许路径和当前用户授权。
- 一个任务只指定一个最终负责的写入角色。
- Reviewer 与 Integration Owner 不替开发 Agent 实现功能。
- `coordinator` 是任务编号、路径占用、状态和证据文件的唯一维护者。

## 2. 核心治理角色

| 角色 | 主要职责 | 主要产出 | 明确禁止 |
| --- | --- | --- | --- |
| `coordinator` | 串行维护任务编号、路径占用、状态和证据，拆分、派发并汇总任务 | 任务单、任务索引、证据报告、协调结论 | 修改需求、替架构决策、实现功能、自行合并 |
| `requirements_owner` | 确认背景、用户、问题、功能范围和需求变更 | 产品背景、需求、范围说明 | 技术选型、架构设计、功能代码 |
| `architecture_owner` | 在需求确认后设计模块边界、契约和技术决策 | 架构决策、接口契约、模块边界 | 擅自增加需求、代替所有模块开发 |
| `repo_maintainer` | 维护仓库、规则、自动检查和开发基础设施 | Git/CI 配置、规则、治理脚本 | 产品功能与业务规则 |
| `qa_reviewer` | 只读检查缺陷、回归、需求偏差、越界和测试缺口 | 审查报告 | 修改文件、创建提交、批准自己的代码 |
| `integration_owner` | 汇总证据、处理集成、给出阶段验收结论 | 验收报告、集成建议 | 重新定义需求、无证据放行、替用户合并 |

## 3. 产品开发角色

| 角色 | 负责范围 | 不负责范围 |
| --- | --- | --- |
| `resource_worker` | 资料、主题、标签、原始链接和原始文件相关功能 | 学习进度、内容解析、AI、RAG、学习 Agent |
| `learning_worker` | 状态、进度、笔记、学习记录、复习和统计 | 原始资料处理、AI 内容生成、RAG |
| `frontend_worker` | 已确认页面、交互、状态呈现和接口调用 | 后端业务规则、数据含义、接口契约决定 |
| `document_worker` | 用户授权资料的正文提取、处理状态和失败说明 | AI 摘要、检索问答、学习计划 |
| `ai_worker` | 用户模型配置、摘要、知识点、术语和练习题 | 资料管理、检索系统、Agent 自动操作 |
| `rag_worker` | 资料范围选择、检索、问答依据和来源引用 | 通用聊天、原始资料管理、任务创建 |
| `study_agent_worker` | 计划建议、受控工具、用户确认和执行记录 | 绕过确认、自由修改其他模块、扩展产品范围 |

## 4. 跨角色协作边界

### 需求到架构

需求负责人说明“要实现什么”，架构负责人决定“如何组织实现”。架构负责人发现需求缺口时只能提出问题，不能代替需求负责人补写产品事实。

### 架构到开发

涉及多个模块时，架构负责人先确定可观察行为和契约。开发 Agent 只能实现已批准的契约，不得各自发明不同接口。

### 开发到审查

开发 Agent 提供完整 diff、检查结果和交接报告。Reviewer 保持只读，只报告问题；已接受问题由原开发 Agent 修复。

### 审查到验收

Reviewer 判断是否存在可操作缺陷；Integration Owner 判断任务是否满足验收门槛。两者都不能代替用户作最终合并决定。

## 5. 角色启用顺序

并非所有角色需要立即参与：

1. 当前阶段：`coordinator`、`requirements_owner`、`architecture_owner`、`repo_maintainer`、`qa_reviewer`、`integration_owner`；
2. 资料与学习管理阶段：加入 `resource_worker`、`learning_worker`、`frontend_worker`；
3. 内容处理阶段：加入 `document_worker`；
4. AI 阅读阶段：加入 `ai_worker`；
5. 个人资料问答阶段：加入 `rag_worker`；
6. 学习助手阶段：加入 `study_agent_worker`。

未启用角色不得提前实现其对应功能。
