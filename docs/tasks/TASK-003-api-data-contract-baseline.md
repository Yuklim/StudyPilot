## 8. 契约要求

### 8.1 文档结构与一致性

1. `API与数据契约基线.md` 是含义解释的权威来源，`openapi-v1.json` 是 HTTP 接口结构的机器可读快照；两者对路径、方法、字段、枚举、状态码和示例必须逐项一致。
2. 每项规则必须标明来源：已确认产品需求、已批准架构决定，或由 `architecture_owner` 在批准范围内作出的技术细化；不得把未来设想写成当前契约。
3. 文档必须提供术语表，并在首次出现时用通俗语言解释 OpenAPI、schema、枚举、分页、幂等、UTC、状态机、乐观并发、令牌等术语。
4. 契约采用版本化 `/api/v1`，说明向后兼容原则，以及以后如何提出、审查和记录破坏性变更；本任务不建立自动代码生成。

### 8.2 HTTP 接口和统一外形

5. 完整列出第一阶段已批准 API 资源组及其具体 HTTP 方法：本地会话、资料、删除预览/执行、主题、标签与资料标签关联、笔记、学习记录、复习、概览统计、主题统计和原始文件下载。
6. 每个接口必须定义：用途、请求头、路径/查询参数、请求体、成功状态码、响应体、可预期错误、是否有副作用、负责模块和至少一组成功/失败示例。
7. 冻结统一成功资源外形、列表分页外形和架构已批准的统一错误外形 `error.code/message/details/request_id`；说明哪些字段面向程序判断，哪些字段面向用户显示。
8. 建立稳定错误码目录，至少覆盖：输入校验、未找到、重复/唯一性冲突、版本或状态冲突、非法状态转换、令牌缺失/错误/过期/重放、来源校验失败、文件类型/大小/状态错误、删除影响变化、路径不可用和未知服务错误。错误信息不得泄露正文、笔记、磁盘路径、SQL、堆栈、完整文件名或令牌。

### 8.3 数据对象、字段和所有权

9. 为 `LearningResource`、`OriginalFile`、`DeletionConfirmation`、`LearningProgress`、`Topic`、`Tag`、`ResourceTag`、`Note`、`StudyRecord`、`ActiveReviewPlan` 和 `ReviewRecord` 建立字段字典。
10. 每个字段必须说明：API 名称、概念类型、示例、创建时是否可写、更新时是否可写、是否必填、是否可空、默认值、长度/范围、是否只读、是否敏感、权威所有者以及数据库任务必须保持的不变量。
11. 明确对象关系、级联/保留语义、唯一性、资料版本与关联版本或等价变更序号；`DeletionConfirmation` 不得随资料级联删除，历史学习/复习记录不得被当前值覆盖。
12. 一份资料必须且只能有一种主要来源：网页链接、上传文件或粘贴内容；明确三种创建请求的互斥字段、修改限制和响应摘要。第一阶段搜索只覆盖标题、来源名称和保存原因；笔记和未解析正文不进入统一搜索。
13. 冻结稳定英文枚举及中文显示标签，至少包括资料来源、五种学习状态、原始文件 `PENDING/READY/FAILED`、复习计划状态和契约需要的结果类型；中文文案变化不得改变已保存代码。

### 8.4 状态、进度和时间

14. 提供学习状态转换矩阵，逐项说明允许、拒绝和需要额外字段的转换；明确手动回到未读时非零进度的处理、100% 进度不自动标记完成、归档/恢复、待复习进入与退出的含义。
15. 明确学习记录与当前状态/进度必须在同一事务中更新；冻结 0～100 的进度范围、时长单位与范围、前后值校验、负值拒绝以及历史不可覆盖规则。
16. 区分“时间点”和“本地日期”：时间点以带时区的 RFC 3339 字符串交换、数据库后续统一保存为 UTC；用户选择的复习日期保持日期语义。明确今天、逾期、本周、跨日、夏令时/时区变化和界面本地显示规则。
17. 明确 `created_at`、`updated_at`、`started_at`、`completed_at` 等字段的自动填充、清空和保持规则；单纯查看或下载不得改变 `updated_at`。

### 8.5 列表、搜索、筛选和并发

18. 冻结一种统一分页方式及默认值、最大值、稳定排序和越界行为；列表响应必须让前端知道当前页信息以及是否还有结果。
19. 为资料、学习记录、复习和统计接口列出允许的搜索、筛选和排序字段、组合规则、空值语义和非法字段错误；不得接受任意数据库列名作为排序参数。
20. 定义更新操作的版本字段或等价乐观并发规则，避免较旧界面静默覆盖较新数据；冲突使用 409 并返回安全、可操作的信息。

### 8.6 本地访问安全协议

21. 冻结规范 UI 来源、可信 `Host`/`:authority`、开发代理、CORS 允许项和 `/api/v1/local-session` bootstrap 的精确请求/响应行为。
22. 明确每次启动生成至少 256 位随机本地令牌，bootstrap 响应 `Cache-Control: no-store`，前端只存内存；令牌不得进入 URL、Cookie、`localStorage`、Git、普通日志或错误响应。
23. 明确所有业务读取、下载和写入都要求 `X-StudyPilot-Token`；写请求还必须严格校验完整 `Origin` 和 Fetch Metadata。缺失、错误、旧令牌、`null`、`same-site`、`cross-site` 和未知值默认在读取请求体、查询数据库或创建文件前返回 403。
24. 用请求判定表覆盖正常同源请求、无令牌读取、恶意简单表单、跨站 fetch、multipart、预检、错误 Host、重复/转发 Host 和非浏览器客户端；不得留下调试后门。

### 8.7 上传、下载和删除协议

25. 冻结第一阶段允许的 PDF、Word、Markdown、TXT 文件识别规则、保守大小上限、文件名处理、媒体类型响应、安全下载头和拒绝原因。扩展名、浏览器媒体类型和原始文件名一律视为不可信输入；本任务只写契约，不选择恶意文件扫描产品能力。
26. 完整定义同卷暂存、校验、SHA-256、`PENDING → READY/FAILED`、原子提升、成功响应门槛、失败清理、启动/定时对账、宽限期孤儿回收和可下载条件。只有 `READY` 可以返回添加成功并下载，不得暗示正文已经解析。
27. 冻结“删除预览—用户确认—执行”接口、影响摘要、专用确认请求头、短时一次性不透明令牌的有效期与消费规则。令牌必须绑定资料版本及原始文件、笔记、学习记录、复习和标签关联的稳定影响集合，不能只绑定数量。
28. 明确执行删除时在事务中重算影响；变化则旧令牌作废并返回 409 与新摘要，过期、重放或绑定错误必须拒绝。说明数据库提交与同卷 trash 移动/恢复/清理的失败语义，但不编写实现。
29. 主题或标签仍被资料使用时默认返回 409 和安全影响信息，不静默连带删除资料；主要主题的实际重分配仍只能由 resources 执行。

### 8.8 OpenAPI 快照

30. `openapi-v1.json` 使用 OpenAPI 3.1.x，包含 `info`、`paths`、`components/schemas` 和必要的安全/参数复用定义；不得包含真实服务器、邮箱、令牌、文件路径或用户数据。
31. OpenAPI 中每个第一阶段接口都必须有稳定 `operationId`、标签、中文摘要、请求/响应 schema、所有已定义状态码和安全示例；下载接口需表达二进制响应，上传接口需表达 multipart。
32. 文档中的字段表、枚举、错误码和示例必须能逐项映射到 OpenAPI；若纯 OpenAPI 无法完整表达事务或安全前置顺序，必须在中文契约中明确说明并从相应操作链接引用。
